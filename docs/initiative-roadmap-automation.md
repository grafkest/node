# Автоматизация построения дорожной карты инициативы

## Цели
- Обеспечить непрерывную занятость сотрудников каждой роли и сбалансировать загрузку по ролям.
- Сформировать оптимальный состав команды под ограничение минимальных сроков реализации.
- Назначить рациональные даты начала для каждой роли без прерываний участия.
- Предложить несколько вариантов дорожной карты при разных числах специалистов в ключевых ролях.

## Входные данные
- **Работы и зависимости**: длительность, тип работы, требования к ролям, граф зависимостей.
- **Ресурсы**: список специалистов с ролью, занятостью по времени (календарь/диапазоны), допустимым количеством параллельных задач.
- **Политики**: максимальная загрузка на специалиста, запрещённые прерывания роли, приоритет оптимизации (минимум сроков, затем баланс ролей).

## Основные ограничения
1. Участие роли непрерывно: после старта роль остаётся в инициативе до окончания её последней работы.
2. Количество специалистов по роли можно увеличивать, но не уменьшать до конца участия роли.
3. Датой старта роли можно управлять, чтобы сгладить конфликты ресурсов.
4. Дорожная карта должна учитывать технологические зависимости работ.

## Алгоритм построения (итеративное уточнение)
1. **Нормализация работ**
   - Строим ориентированный ацикличный граф (DAG) по зависимостям.
   - Для каждой работы фиксируем требуемые роли и длительность.
2. **Оценка узких мест по ролям**
   - Для каждой роли считаем суммарный объём работ и текущую доступность специалистов.
   - Определяем минимально необходимое количество специалистов по роли, деля объём работ на доступные слоты (округление вверх).
3. **Поиск стартовых дат ролей**
   - Для каждой роли выбираем минимальную дату, когда:
     - все предшествующие по зависимостям работы роли стартуют не раньше;
     - специалисты роли доступны (учёт их текущих занятостей);
     - участие роли будет непрерывным до её последней задачи.
   - Используем двоичный поиск по дате старта роли + проверку достижимости графа, чтобы минимизировать общую длительность.
4. **Планирование с учётом параллельности**
   - Применяем модифицированное расписание критического пути (CPM) с ограничениями ресурсов:
     - Сначала считаем ранние/поздние даты работ без ограничений ресурсов.
     - Затем запускаем алгоритм Resource-Constrained Project Scheduling (RCPSP) с эвристикой **serial schedule generation**: сортируем работы по ранним датам и критичности, назначаем начало с учётом доступности ролей и непрерывности участия.
   - Если роль перегружена, добавляем ещё одного специалиста роли и пересчитываем расписание.
5. **Генерация альтернатив**
   - Для ролей с перегрузкой строим варианты с 1…N специалистами (N — доступное количество сотрудников роли или ограничение бюджета).
   - Для каждого варианта повторяем шаги 3–4 и фиксируем итоговую длительность, даты привлечения ролей и распределение работ.
6. **Выбор оптимального варианта**
   - Основной вариант — минимальная длительность инициативы.
   - Дополнительно показываем варианты с близкой длительностью (например, в пределах +10%) но с меньшим числом привлечённых специалистов.

## Формат результата
- **Дорожная карта**: календарь работ с привязкой к ролям и специалистам, видимые критические пути.
- **Планы привлечения ролей**: для каждой роли — дата старта, количество специалистов, диапазон участия.
- **Альтернативы**: таблица «количество специалистов → длительность инициативы → стартовые даты ролей → загрузка».

## Технические рекомендации реализации
- Использовать библиотеку планирования (например, `rcpsp` в Python) или собственную реализацию serial schedule generation.
- Хранить данные о занятости специалистов в виде таймлайнов (интервалы занятости) для быстрых проверок доступности.
- В UI показывать сравнение альтернатив (график Gantt + сводка по ролям) и подсветку ролей с перегрузкой.
- Добавить API-метод: `POST /api/initiatives/:id/schedule` с параметрами варианта (число специалистов по ролям) для расчёта разных сценариев.
